# Grammar Lab

Інтерактивний тренажер з граматики англійської: теорія українською, 6 механік вправ (порядок слів, вибір, пропуски, викреслювання, ABCD і переклад речень),
персональний доступ для кожного учня і кабінет викладача зі статистикою помилок.

Сайт — статичні сторінки на GitHub Pages. Дані, авторизація і права доступу — у Supabase.

## Структура

```
index.html              тренажер (вхід → теорія і вправи)
teacher.html            кабінет викладача
js/config.js            адреса Supabase і публічний ключ
js/api.js               усі запити до бази
js/engine.js            рендер вправ і перевірка відповідей
js/auth.js              вхід у тренажер
js/teacher.js           логіка кабінету
js/exercise-text.js     текстовий опис вправи для статистики
js/translate.js         перевірка речень для механіки «переклад» (токенізація, порівняння з еталонами, пояснення помилок)
tests/translate.test.js приклади перевірки (node --test tests/translate.test.js)
supabase/               SQL-скрипти та серверна функція
```

## Supabase: порядок розгортання з нуля

У SQL Editor, по черзі:

1. `01_schema.sql` — таблиці та правила доступу
2. `02_content_*.sql` — контент тем
3. `03_make_me_teacher.sql` — зробити свій акаунт викладачем
4. `04_attempts_delete_policy.sql` — хто може стирати історію спроб
5. `05_teacher_cabinet.sql` — захист ролі, email у профілях
6. `06_theory_structure.sql` — структура блоків теорії (kind, content_json)
7. `07`–`10_theory_*.sql` — теорія у кроковому форматі: прикметники, іменники, прислівники, артиклі
   (спочатку `08`, бо він розширює список типів блоків; повторний запуск безпечний)
8. `11_modal_verbs.sql`, `12_pronouns.sql`, `13_verbals.sql`, `14_comparisons.sql` — нові теми повністю: тема, теорія у кроковому форматі й вправи.
   Id вправ мають префікс теми (`modal_`, `pron_`, `verb_`), щоб не перетнутися з наявними.
9. `15_exercise_groups.sql` — єдиний зведений файл: групує вправи всіх тем за номерами з підручника («Exercise N»), розбиває кожну тему на підтеми (колонки `topics.subtopics`, `theory_blocks.subtopic`, `exercises.subtopic`) і ділить Verbals на три окремі теми — Infinitive, Gerund, Participle (призначення учням копіюються). В кінці виводить контрольні таблиці. Можна запускати повторно.
10. `16_conditionals.sql`, `17_reported_speech.sql` — теми «Умовні речення, Wishes, Unreal Past» і «Непряма мова»: теорія, вправи та підтеми. Потребують `15_exercise_groups.sql` (колонки підтем додаються й тут, тож порядок не критичний). Повторний запуск безпечний.

11. `18_tenses_present.sql`, `19_tenses_past.sql`, `20_tenses_future.sql` — три теми «Дієслівні часи»: теперішні, минулі, майбутні (по 4 часи + підтема «усе разом»). Вправи тут включають нову механіку `translate`, тому кожен із цих файлів розширює обмеження `exercises_type_check` (повторний запуск безпечний). Номери вправ у цих темах придумані (в PDF вони не нумеровані єдиним способом).

Потім **Edge Functions → Deploy a new function → Via Editor**, назва `admin-users`,
вміст — `supabase/functions/admin-users/index.ts`. У налаштуваннях функції вимкнути
**Verify JWT with legacy secret** (функція перевіряє користувача сама).

## Механіка «переклад»

Тип `translate` у `exercises`. Учень вписує речення (з українського, зі слів-підказок, виправляє помилку, ставить питання
до виділених слів або переписує за зразком), а перевірка порівнює його з базою еталонів `answers` у `payload`.

- `kind`: `translate` | `build` | `fix` | `question` | `rewrite`;
- `answers`: усі прийнятні варіанти (скорочення, синоніми, порядок обставин);
- `tense`: коди часів, що перевіряються (`pres_simple`, `past_perf`, `fut_cont`, `be_going_to`…) — за ними генеруються пояснення помилок;
- `traps` (необов'язково): типові помилки з коментарем українською.

Перевірка (`js/translate.js`) розбиває речення на токени з розкриттям скорочень, вирівнює їх із найближчим еталоном і показує
пояснення: не той час, забутий допоміжний, порядок слів, дієслово стану в Continuous тощо. Якщо речення відрізняється від еталона
лише синонімом, воно позначається як «майже» й учень може прийняти його сам.

Вправа на пропуски (`gap`) тепер підтримує кілька пропусків в одному реченні (`blanks`).

## Як влаштований доступ

- Учень бачить лише теми, які відкрив викладач, теорію й вправи не вище призначеного рівня,
  і не бачить вправ, схованих для нього окремо. Це забезпечує база (RLS), а не інтерфейс:
  без входу запити повертають порожнечу.
- Персональні вправи — рядки `exercises` із заповненим `student_id`.
- Кожна перевірка відповіді пишеться в `attempts`. Учень не може стерти свою історію —
  це може лише викладач.
- Створення акаунтів і зміна паролів — через серверну функцію `admin-users`:
  службовий ключ існує лише всередині Supabase.

## Після зміни будь-якого js-файлу

Збільшити номер `?v=N` у тегах `<script>` в `index.html` і `teacher.html`.
Інакше браузер може віддати учневі стару версію з кешу.

## Обмеження, про які варто памʼятати

- Безкоштовний Supabase присипляє проєкт після тижня без звернень — перше відкриття після паузи повільне.
- Supabase віддає максимум 1000 рядків за запит; усі завантаження йдуть сторінками через `fetchAll` в `js/api.js`.

## Оформлення та палітри

Усі кольори сайту — CSS-змінні (`--c-…`), які задає обрана палітра з `js/palettes.js`;
токени Tailwind описані в `js/theme.js`. Перемикач «Колір оформлення» стоїть унизу бічного меню,
вибір зберігається в `localStorage` (кабінет викладача підхоплює його автоматично).

Палітри (крім типової «Океан» з DESIGN.md) генеруються за принципами Material You: одне «зерно»
кольору → тональні палітри HCT → токени; акценти категорій слів гармонізуються із зерном.
Щоб додати палітру, допишіть рядок у `SEEDS` у `scripts/gen-palettes.mjs` і перегенеруйте файл:

```
npm i --no-save @material/material-color-utilities esbuild
npx esbuild scripts/gen-palettes.mjs --bundle --platform=node --format=esm --outfile=/tmp/gen.mjs
node /tmp/gen.mjs > js/palettes.js
```

Після змін у `js/*.js` збільшуйте `?v=N` у `index.html` і `teacher.html`.
